# Flutter 6.1：埋点 SDK 封装 v0.1-alpha 设计稿

日期：2026-05-03  
状态：已确认（用户“确认 Flutter 6.1 设计”）  
对应 WBS：6.1 埋点 SDK 封装（Flutter）

---

## 1. 背景

当前 Flutter 侧已经完成：

- 匿名登录
- 录音 + 上传
- 推理调用 + 结果页
- 问题库列表/详情页
- 分享文案复制 + 系统分享
- 复测对比 + 成就

后端已提供埋点接收接口：

- `POST /v1/analytics/event`

支持字段：

- `event_name`
- `ts_ms`
- `user_id`
- `session_id`
- `platform`
- `app_version`
- `content_version`
- `request_id`
- `payload`

因此当前可以直接补齐 Flutter 端 telemetry 模块，作为 5.4 看板与 6.3 指标聚合的前置。

---

## 2. 目标（DoD）

1) Flutter 端提供统一的埋点入口  
2) 自动补齐公共字段：
   - `ts_ms`
   - `user_id`
   - `session_id`
   - `platform`
   - `app_version`
   - `content_version`（若当前页面有）  
3) 接入 MVP P0 关键事件  
4) 埋点发送失败时本地缓冲，后续自动重试  

---

## 4. 公共字段策略

### 4.1 user_id

来源：

- `LocalStore.getUserId()`

### 4.2 session_id

策略：

- App 启动时生成一次
- 会话期间复用
- MVP 不做复杂前后台切分

### 4.3 platform

来源：

- `Platform.isIOS / Platform.isAndroid`

### 4.4 app_version

v0.1-alpha 先用固定字符串：

- `0.1.0`

后续可切到 `package_info_plus`

### 4.5 content_version

策略：

- 若页面已有接口返回 `content_version`，则传入
- 没有则允许为空，不强行推断

## 5. SDK 结构设计

建议新增：

- `apps/mobile/lib/telemetry/telemetry_client.dart`
- `apps/mobile/lib/telemetry/telemetry_store.dart`

### 5.1 TelemetryClient

职责：

- 对外提供统一 `track(...)`
- 自动补齐公共字段
- 发送到 `/v1/analytics/event`
- 失败时落本地缓冲

建议接口：

```dart
class TelemetryClient {
  Future<void> track(
    String eventName, {
    String? requestId,
    int? contentVersion,
    Map<String, dynamic>? payload,
  });

  Future<void> flush();
}
```

### 5.2 TelemetryStore

职责：

- 本地保存待重试事件队列
- 控制队列大小

建议策略：

- 最多保留 `50` 条
- 先进先出

## 7. 离线缓冲策略

当调用 `/v1/analytics/event` 失败时：

- 事件写入本地队列

后续触发 `flush()` 的时机：

- App 启动后
- 关键页面进入时（例如 HomeScreen / ResultScreen）

实现策略：

- 逐条发送
- 成功即删除
- 失败停止本轮 flush，等待下次重试

---

## 8. 非目标（本轮不做）

- 不做埋点批量上传接口
- 不做复杂会话切分
- 不做埋点开关后台配置
- 不做完整 A/B 实验字段管理

---

## 9. 验收标准（DoD）

1) 关键 P0 事件都能发到 `/v1/analytics/event`  
2) 自动附带公共字段  
3) 网络失败时事件不会立即丢失，而是进入本地缓冲  
4) 后续再次进入 App 或页面时可以自动 flush
