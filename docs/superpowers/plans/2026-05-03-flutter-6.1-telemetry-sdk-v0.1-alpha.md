# Flutter 6.1 Telemetry SDK v0.1-alpha Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Flutter 客户端实现埋点 SDK（track + 离线缓冲 + flush 重试），并把 P0 关键事件接入 Home/Record/Result/Problems/ProblemDetail 页面，发送到 `POST /v1/analytics/event`，为后续 6.3 指标聚合与 5.4 后台看板提供稳定数据源。

**Architecture:** 新增 `TelemetryClient`（负责拼公共字段、发送、失败入队、flush）与 `TelemetryStore`（shared_preferences 队列）；`ApiClient` 新增 `postJsonAbsolute` 或复用 baseUrl 发送；页面在关键点调用 `telemetry.track(...)`，并在 `HomeScreen` 启动时 `flush()`。

**Tech Stack:** Flutter (Dart) + shared_preferences + http。

## Task 2: TelemetryClient（拼公共字段 + 发送 + 失败入队）

**Files:**
- Create: `apps/mobile/lib/telemetry/telemetry_client.dart`
- Modify: `apps/mobile/lib/api/api_client.dart`

- [ ] **Step 1: ApiClient 增加 analytics 发送方法**

在 ApiClient 中新增：

```dart
Future<void> postAnalyticsEvent(Map<String, dynamic> body) async {
  await postJson('/v1/analytics/event', body);
}
```

> 注意：`postJson` 会自动带 Authorization，符合后端要求（user_id 也可空，但我们尽量传）。

- [ ] **Step 2: TelemetryClient 生成 session_id**

v0.1 策略：首次使用时生成并保存（LocalStore setString），键：
`telemetry_session_id_v1`

- [ ] **Step 3: track()**

```dart
Future<void> track(
  String eventName, {
  String? requestId,
  int? contentVersion,
  Map<String, dynamic>? payload,
}) async
```

拼装字段：
- event_name
- ts_ms = now
- user_id = LocalStore.getUserId()
- session_id = 本地生成/读取
- platform = ios/android
- app_version = "0.1.0"
- content_version（若传入则附带）
- request_id（若传入则附带）
- payload（map，不传则 {}）

发送失败：`TelemetryStore.enqueue(event)`，并直接 return（不抛出到 UI）。

- [ ] **Step 4: flush()**

策略：
- 取队列 list
- 逐条发送
- 发送成功即计数，连续成功 N 条后 removeFirstN(N)
- 若中途失败：停止 flush

- [ ] **Step 5: Commit**

```bash
git add apps/mobile/lib/telemetry apps/mobile/lib/api/api_client.dart
git commit -m "feat(mobile): add telemetry client with flush"
```

## Task 4: 页面接入 P0 事件

**Files:**
- Modify: `apps/mobile/lib/screens/home_screen.dart`
- Modify: `apps/mobile/lib/screens/record_screen.dart`
- Modify: `apps/mobile/lib/screens/result_screen.dart`
- Modify: `apps/mobile/lib/screens/problems_screen.dart`
- Modify: `apps/mobile/lib/screens/problem_detail_screen.dart`

- [ ] **Step 1: HomeScreen**

在 bootstrap 成功后：
- `telemetry.track('app_open')`
- 调 `telemetry.flush()`（把历史队列冲掉）

- [ ] **Step 2: ProblemsScreen**

列表加载成功后：
- `telemetry.track('problem_list_viewed', contentVersion: cv, payload: {'source':'tab'})`

- [ ] **Step 3: ProblemDetailScreen**

详情页加载成功后：
- `telemetry.track('problem_viewed', payload:{'problem_id': id}, contentVersion: cv)`

- [ ] **Step 4: RecordScreen**

请求 upload-url 前：
- `upload_url_requested`（payload: duration_ms/content_type/problem_id/entry）

上传成功：
- `audio_upload_succeeded`（payload: audio_id/bytes/problem_id）

上传失败：
- `audio_upload_failed`（payload: audio_id/error_code）

> v0.1：如果拿不到 bytes，就不传。

- [ ] **Step 5: ResultScreen**

推理开始前：
- `inference_started`（payload: entry/problem_id/context_keys）

推理成功：
- `inference_succeeded`（request_id + payload: model_version/primary_intent_code/confidence）

推理失败/降级：
- `inference_failed`（request_id + payload: degraded/degraded_reason）

成功展示结果页：
- `result_page_viewed`（request_id + payload: problem_id/primary_intent_code）

反馈提交成功后：
- `feedback_submitted`（request_id + payload: helpful/problem_id）

分享点击/完成：
- `share_clicked` / `share_completed`（request_id + payload: share_channel/asset_type）

复测：
- `retest_started`（payload: problem_id/baseline_request_id）
- `retest_completed`（payload: problem_id/delta_direction/delta_value）
