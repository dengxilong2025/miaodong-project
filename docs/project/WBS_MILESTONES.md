# 喵懂（喵测）WBS + 里程碑版本计划

面向团队规模：1-2 人为主（可按需找外援）。
目标：**先低成本验证，再补资质上架商店**；所有阶段共享同一套 Go API / 内容系统 / 指标系统。

> 状态标签：`已实现` = 代码+测试已落地；`进行中` = 当前迭代；`计划中` = 已排期未开发。
> 本文档是开发计划的唯一入口；代码完成一个工作包后，必须同步更新本文档的状态。

## 1.1 渠道策略（与 ADR-0004 对齐）

| 阶段 | 渠道 | 是否需要公司 | 目的 |
|---|---|---|---|
| 0 | H5 / 预约页 / 小红书 | 不需要 | 验证录音意愿、结果有用性、复测意愿 |
| 1 | TestFlight + Android APK 内测 | 不需要（Apple 个人账号即可） | 验证真实 App 体验与留存 |
| 2 | 个体户/有限公司 + 软著 + App 备案 | 需要 | 满足国内商店上架前置条件 |
| 3 | 国内安卓商店 + 中国区 App Store | 需要 | 正式获客 |
| 4 | 会员/带货/商城 | 需要（支付/ICP 等） | 商业化，MVP 不做 |

**MVP 不做**：支付、订单、带货、复杂推荐、微服务拆分、多租户。

## 5. 文档与代码对齐规则

- 任何工作包完成，必须同时更新：本文档状态、相关设计文档、测试说明。
- 任何接口/数据结构变更，必须先改 `docs/tech/API_CONTRACT.md` 或 `docs/tech/CONTENT_DATA_MODEL.md`，再改代码。
- 每日至少一次：本地测试 → 文档对齐 → commit → push → CI 绿。
- 详见 `docs/project/DEV_WORKFLOW.md`。
